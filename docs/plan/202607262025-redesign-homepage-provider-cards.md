# 主页平台卡片重设计

## Summary

把卡片重排为移动端优先的紧凑账户读数：平台身份与操作形成一个头部，余额以“币种 + 大金额”成对展示，更新时间并入右侧操作信息区，不再单独占据底部整行。

```text
┌────────────────────────────────┐
│ [Logo] OpenRouter    余额趋势 › │
│                     3 分钟前更新 │
│                                │
│ USD  12.34     CNY  86.20      │
└────────────────────────────────┘
```

延续现有深海配色、字体和卡片轮廓；唯一重点视觉是紧凑的多币种“大号读数带”，不引入新依赖或额外装饰。

## Implementation Changes

- 头部改为稳定的左右布局：左侧 logo 与平台名称垂直居中且保持同一视觉高度；长名称继续省略，不能挤压右侧操作区。
- 详情入口由圆形纯箭头改为带 44px 触控区的“余额趋势 ›”文字链接，继续进入当前平台并默认选中首个币种。
- 更新时间收进右侧操作区：正常时只显示相对更新时间；`RUNNING`、`FAILED` 在时间后追加状态；从未刷新时只显示“等待首次更新”。
- 余额区域移除左右两端拉开的结构，改为可换行的紧凑读数组：每组按照 `币种  大金额` 相邻排列，多币种从左到右展示；金额继续保持当前主视觉级别。
- 删除旧的独立 `provider-meta` 分隔行和已废弃状态行样式；“平台暂不可用”和失败详情继续保留，并跟随紧凑信息区展示。
- 同步调整加载骨架，使其与新头部、操作区和余额读数结构一致。
- 不修改后端 API、数据结构、币种顺序、详情页或余额格式化规则。

## Verification

- 检查 `SUCCESS`、`RUNNING`、`FAILED`、`NEVER_REFRESHED` 四种状态，以及有无历史成功时间的组合。
- 检查单币种、多币种、空余额、超长平台名和较长金额，确保 320px 宽度下不横向溢出。
- 确认 logo 与平台名称垂直居中，“余额趋势”具有明确焦点样式和至少 44px 触控区。
- 确认失败原因仍可展开，详情链接仍携带首个币种查询参数。
- 仅进行静态 diff 和空白检查；按项目约定不运行前端构建、TypeScript、lint、Vite 或启动命令。

## Assumptions

- 保留当前尚未提交的“正常状态不显示、异常状态并入更新时间”改动，并将其整合进新卡片结构。
- “保留大金额”指维持金额的视觉主次，不保证所有多币种永远单行；空间不足时整组换行，不拆开币种和金额。
- 本次不提交代码，除非用户后续明确要求 commit。
