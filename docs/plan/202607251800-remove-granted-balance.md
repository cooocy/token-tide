# 删除赠送余额

## 背景

余额历史的核心用途是记录各平台当前实际可消费的金额。赠送余额只是部分平台提供的余额组成，跨平台并不统一；充值余额删除后，单独保留赠送余额也无法形成完整且一致的余额来源视图。因此历史记录仅保留时间、币种和可用余额。

## 实施方案

1. 新增 Alembic 迁移，从 `balance_snapshot` 删除 `granted_amount`；降级时恢复为可空的 `NUMERIC(20, 2)` 列。
2. 从 SQLAlchemy Model、Provider 统一读数、余额持久化和 API Schema 中删除 `granted_amount`。
3. DeepSeek 不再解析 `granted_balance`，SiliconFlow 不再解析赠送余额字段；所有 Provider 只生成统一的可用余额读数。
4. 从前端 API 类型和平台历史表格中删除赠送余额，历史表格最终只显示时间、币种和可用余额。
5. 更新 Provider、Service 和迁移测试，确认接口与持久化模型不再包含余额组成字段，并验证迁移会删除和恢复数据库列。

## 兼容性

- API 响应不再返回 `granted_amount`，属于有意的字段删除。
- 升级迁移会永久删除已有的赠送余额历史数据；降级只恢复空列，无法还原已删除的数据。
- 旧迁移和历史方案文档保留当时的结构记录，不进行回写。

## 验证

- 使用文本搜索确认运行时代码和前端不存在 `granted_amount` 或赠送余额展示。
- 运行 `git diff --check`。
- 不执行任何 Python 或前端命令；测试、类型检查、构建和启动由用户执行。
