# 优化 TokenUsage 入口与详情页

## Summary

- 将 TokenUsage 从余额标题附属链接提升为顶部同级入口，形成“余额看板 / TokenUsage”双入口导航。
- 保留现有深海配色和字体体系，通过更清晰的层级、留白和响应式布局优化详情页。

## Implementation Changes

- 首页增加双入口导航，当前页突出“余额看板”，`TokenUsage` 独立跳转 `/usage`；删除余额标题旁的“查看使用量”链接。TokenUsage 页采用相同导航逻辑并标识当前入口。
- 详情页标题改为主标题 `TokenUsage`、副标题 `Token 用量`。总量区域仅保留 `TOTAL` 标题，移除“n 天使用量”副标题；请求次数继续显示精确整数。
- 新增统一 Token 紧凑格式：小于 1,000 显示原值，之后采用 `K / M / B`，最多一位小数并去除无意义的 `.0`。应用于总量、Token 分布、选中日期、工具拆分和模型排行；可访问文本保留精确值。
- 将总量下方的 `TOKENS` 改为 `TOKENS 分布`，调整分布卡片的间距和移动端换行，避免长数字截断。
- 图表标题改为 `DAILY TOKEN` / `用量潮线`，移除“本地日界线”。选中柱状图后的读数固定为两行：第一行显示日期与当天 Token 总量，第二行显示 Claude、Codex、OpenCode 工具拆分；移动端不再挤压为左右两栏。
- 优化筛选器、Hero、图表和模型排行之间的节奏、对齐和视觉权重，强化选中柱的反馈，同时保持键盘焦点、触控区域和 reduced-motion 支持。
- 不修改后端接口、查询参数、URL 筛选状态或 Token Usage 数据结构。

## Test Plan

- 静态检查双入口的当前态、链接目标、返回行为以及旧入口是否完全移除。
- 覆盖 Token 格式边界：`0`、`999`、`1K`、小数 K、`1M`、`1B`、无效数值及临界进位。
- 检查今天、7 天、30 天及各工具筛选下的加载、失败、空数据和有数据状态。
- 检查柱状图默认选择、点击切换、两行说明、零用量日期、30 天密集柱状图，以及桌面与 320px 移动端布局。
- 仅执行静态引用检查和 `git diff --check`；前端构建、类型检查和运行验证由用户执行。

## Assumptions

- 双入口中的余额入口显示为“余额看板”，Token 入口严格显示为 `TokenUsage`。
- `K / M / B` 只用于 Token 数；请求次数、模型数量和百分比维持现有精确展示。
- 本次不新增统计维度、日期范围、图表类型、动画框架或后端能力。
