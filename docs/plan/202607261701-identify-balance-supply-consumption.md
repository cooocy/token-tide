# 识别余额补给与消耗

## 目标

基于同一平台、同一币种的相邻余额快照，识别每次余额变化属于补给、消耗还是无变化，并在余额历史页展示事件与当前查询区间汇总。

## 数据语义

- 当前余额减去上一条余额得到 `change_amount`。
- `change_amount > 0` 为 `SUPPLY`，表示补给。
- `change_amount < 0` 为 `CONSUMPTION`，表示消耗。
- `change_amount = 0` 为 `UNCHANGED`。
- 若不存在上一条同币种快照，变化字段为空，不臆测事件。
- 查询带 `start-time`、`end-time` 或 `limit` 时，服务仍向返回区间之前查找一条同币种快照，以正确识别第一条返回记录。
- 金额继续遵循现有两位小数和 UTC `Z` 时间契约。

## 实施步骤

1. 扩展历史点响应模型，增加可空的变化金额与变化类型字段。
2. 在 `BalanceService.balance_history` 中按同平台、同币种快照计算相邻差值，并覆盖首条记录的前序快照查询。
3. 增加服务层测试，覆盖补给、消耗、无变化、无前序记录、币种隔离以及受限查询首条记录。
4. 同步前端历史类型，在历史页计算区间补给/消耗汇总，并为每条记录展示对应事件。
5. 补充现有视觉体系下的事件样式，保持移动端布局稳定。
6. 更新 README 的历史接口说明与功能描述。
7. 仅执行静态差异检查；Python 测试和前端构建、类型检查由用户执行。

## 验收标准

- 历史接口中的每个点都能在有前序快照时返回固定两位小数的有符号变化金额和明确变化类型。
- 不同币种之间不会互相计算差值。
- 历史页能区分并显示“补给”“消耗”和无变化记录。
- 历史页能显示当前已加载区间的补给总额与消耗总额。
- 不新增数据库迁移，不改变定时刷新和手动刷新 API 的兼容性。
