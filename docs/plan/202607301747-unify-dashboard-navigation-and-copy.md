# 统一余额与 Token 用量页面结构及文案

## 目标

- 统一余额看板与 Token 用量两个一级页面的产品身份和导航结构，消除 Token 用量页同时像一级页面和二级详情页的问题。
- 调整移动端首屏信息层级，让余额列表或 Token 总用量更早出现。
- 移除“潮位”“潮线”等意象化专有名词，改用用户能够直接理解的余额、历史、趋势、变动和每日用量等领域词汇。
- 保留现有深海配色、字体和数据展示风格，不修改后端接口及数据语义。

## 最终文案体系

### 一级导航与 Token 用量

| 当前位置 | 当前文案 | 调整后 |
| --- | --- | --- |
| 一级导航 | `TokenUsage` | `Token 用量` |
| Token 用量页标题 | `TokenUsage` / `Token 用量` | `Token 用量` |
| Token 图表标题 | `用量潮线` | `每日用量` |

- TypeScript 类型、组件名、接口字段、API 路径和环境变量中的 `TokenUsage` / `token_usage` / `token-usage` 不属于可见文案，不做重命名。

- 同步更新链接、加载状态、空状态和无障碍标签中的对应词语。
- README 中面向用户的“余额潮位历史”同步改为“余额历史”；既有 `docs/plan/` 是历史执行记录，不回写旧计划。

## 页面结构

### 一级页面

余额看板与 Token 用量共用稳定的 TokenTide 品牌头和一级导航，不在 Token 用量页额外显示返回按钮或第二套品牌标题。

```text
┌──────────────────────────────┐
│ TokenTide                    │
│ [余额看板]      [Token 用量] │
├──────────────────────────────┤
│ 当前页面的核心内容           │
└──────────────────────────────┘
```

### 余额详情

余额详情继续采用“返回按钮 + 平台身份”的二级页面结构，不显示一级导航。

```text
┌──────────────────────────────┐
│ ‹  OpenRouter · 余额历史     │
├──────────────────────────────┤
│ 当前余额与区间增减           │
│ 余额趋势                     │
│ 余额变动                     │
└──────────────────────────────┘
```

## 实施步骤

1. 抽取或整理一级页面共用页头，使余额看板和 Token 用量页使用同一 TokenTide 品牌区与 `ProductNavigation`；删除 Token 用量页的返回按钮和重复品牌标题。
2. 将首页顶部成功平台比例移除。`SUCCESS` 只代表最近一次刷新成功，不能继续用绿色脉冲和“健康平台”比例表达整体健康状态；异常状态仍在对应平台卡片中显示。
3. 收紧余额看板页标题区的垂直留白，保留“余额看板”作为清晰标题，让平台余额卡片更早进入移动端首屏；不改变卡片金额、币种和异常状态的数据结构。
4. 重排 Token 用量首屏：先展示“Token 用量”及选定范围的总量，再将时间和工具筛选作为总量的上下文控制，避免筛选器挡在核心结果之前。
5. 总量继续使用紧凑数字作为主读数，同时在可见辅助文本中提供精确 Token 数，不再只依赖桌面端 `title` 查看完整值。
6. 重组五项 Token 拆分：输入、输出作为主要拆分；缓存写入、缓存读取和推理作为次级明细。移动端不再使用不完整的 `3 + 2` 等宽网格。
7. 改造每日用量图表的移动端选择方式：整个绘图区支持按横向位置选择最近日期，并提供键盘方向键切换；30 天数据不要求用户准确点击狭窄柱体。
8. 将筛选器和其他主要交互控件的触控高度统一到至少 44px，保留明确的 `focus-visible` 和选中状态。
9. 按“最终文案体系”替换余额页、Token 用量页、共享导航、无障碍标签及 README 中的可见文案，并全局检查不再残留 `TokenUsage`、`余额潮位`、`用量潮线` 等旧界面词语。

## 视觉约束

- 延续 `#071820` 深海底色、`#32d6c5` 主强调色及现有数据字体，不引入新的主题或依赖。
- 页面记忆点由真实数据读数、余额趋势和每日用量图表承担，不再依赖“潮位”“潮线”等命名营造风格。
- 减少重复的品牌标题、英文眉题和等权重卡片；英文眉题只用于辅助区分真实的数据模块。
- 优先保证 320px 宽度下的首屏层级、长数字、长模型名、30 天图表和工具筛选可用性。

## 验证

- 静态检查余额看板与 Token 用量页拥有一致的品牌头和一级导航，Token 用量页不再出现返回按钮。
- 检查余额详情仍能返回余额看板，且详情页不显示一级导航。
- 全局搜索可见字符串，确认：
  - `TokenUsage` 已从界面文案中替换为 `Token 用量`；
  - `余额潮位` 已分别替换为 `余额历史`或`余额趋势`；
  - `用量潮线` 已替换为 `每日用量`；
  - 代码类型、接口路径和历史计划未被误改。
- 静态检查加载、失败、空数据、有数据及筛选切换状态的文案和层级。
- 检查 320px、常见手机宽度和桌面布局下的总量、Token 拆分、筛选器及 7 天/30 天图表。
- 仅执行静态引用检查和 `git diff --check`；前端构建、类型检查、运行和视觉截图验证由用户执行。

## 非目标

- 不修改 Token Usage 或余额的后端接口、查询参数、数据模型及统计口径。
- 不修改路由路径 `/usage` 和 `/providers/:provider/history`。
- 不重做品牌 Logo、PWA 图标、全局配色或字体体系。
- 不回写既有计划文件中的历史文案。
