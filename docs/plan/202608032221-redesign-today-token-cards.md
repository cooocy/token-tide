# 今日 Token 三卡布局与总计统一

## Summary

- 将「今日」视图完整改为与「总计」相同的三卡布局：Token 读数、按工具、按模型。
- 三张卡片的标题、结构、样式、配色和响应式布局均原样复用总计视图。
- 仅数据范围不同：今日使用浏览器本地当天数据，总计继续使用全部历史数据。

## Implementation Changes

- 今日读数卡复用 `UsageTokenReading`，固定显示 `TOKEN BREAKDOWN / Tokens 分布`，包含紧凑总量、精确 Token 数、请求数和五项 Token 明细；明细标签使用「今日明细」。
- 今日增加与总计一致的两张 `UsageDistributionChart`：
  - `TOOL SHARE / 按工具`：使用今日各工具 Token 汇总、既有工具配色和今日非零工具数量。
  - `MODEL SHARE / 按模型`：使用今日模型汇总、既有多色模型调色板、“其他”归并规则和今日非零模型数量。
- 调整工具、模型分布转换函数，使 `TokenUsageSummary` 与 `TokenUsageOverview` 共用同一套映射逻辑。
- 今日直接复用 `usage-overview-grid` 和三卡加载骨架，确保桌面三列、移动端纵向排列及卡片圆角完全一致。
- 删除原 `TodayUsageSnapshot`、工具贡献条、四工具列表、百分比计算和全部 `usage-today-*` 专属卡片样式。
- 不修改后端、API 响应、URL 参数、加载与重试机制，或其他视图的数据口径。

## Test Plan

- 静态确认今日仍查询浏览器本地当天零点至当前时间，并且不携带工具过滤条件。
- 检查三张今日卡片的标题、结构、工具颜色、模型颜色和中心数量与总计卡片规则一致。
- 覆盖正常数据、零用量、单一工具/模型、超过五个模型、大数值、加载失败和重试状态。
- 检查桌面三列布局及 320–420px 移动端纵向布局，无数值截断或横向溢出。
- Agent 仅执行源码检查和 `git diff --check`；构建、类型检查、lint 与运行验证由用户执行。

## Assumptions

- 「原样展示」包括总计视图现有的英文标题、中文标题、圆环图、图例、颜色和响应式布局。
- 今日按工具、按模型的数据来自现有 `/token-usage/summary` 响应，无需新增请求或后端能力。
- 两个视图可以使用相同标题，因为顶部菜单已经明确区分「今日」与「总计」的数据范围。
